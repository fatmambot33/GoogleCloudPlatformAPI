# Roadmap

The roadmap is managed through GitHub issues, pull requests, milestones, and releases.

## Priority Order

1. Reliability and security.
2. API consistency and backward compatibility.
3. Documentation and examples.
4. Testing and type safety.
5. Developer experience and performance.
6. New services and features.

## Operating Model

- Every roadmap item must support `PRODUCT.md`.
- Each meaningful change starts from a focused GitHub issue.
- Issues should define the problem, scope, acceptance criteria, and compatibility impact.
- Milestones group work into releases.
- Pull requests should close or reference an issue.
- Completed user-facing changes are recorded in `CHANGELOG.md`.
- Releases follow `RELEASE.md` and semantic versioning.

## Current Direction

The next minor release should focus on repository standardization, API consistency, complete typing and documentation, stronger tests, predictable errors, and release automation before expanding product scope.
